# E01: reproducible baseline pilot

**Historical pilot:** the recorded 1,500-run results below used the previous
30-second member cooldown. That behavior has since been removed at the user's
request. Those results are retained for provenance and do not describe the
current model. Start the revised response model with
[the small E01-B example](e01b-responses.md). The original E01 panel still uses
per-recommendation acceptance probabilities; E01-B uses fixed member cohorts.

Start here before adding member modes, sensing phases, or learned policies.
The executable panel is `configs/experiments/e01.yaml`.

## Source and scope

This implements `Experiment plan!A6:J6` in
`../../outputs/gym-scenarios-20260929/gym-scenario-matrix.xlsx`, prepared
29 September 2026. Source SHA-256:
`6edee2869b7e1f818b29cce51b27acb696d10e540bad178f922a5e4fd0ce5a5a`.
Scenario requirements are in `Scenario matrix!A6:O6`, `A9:O9`, `A22:O23`.
The workbook remains the original planning source; this document records the
implementation and run evidence separately.

| Workbook row | Executable regimes | What is exercised |
| --- | --- | --- |
| S01 | `S01_quiet` | Low load, fresh sensing, fixed visit durations. |
| S04 | `S04_accept_060`, `_080`, `_095` | Per-advice acceptance 0.6 / 0.8 / 0.95; current behavior uses immediate independent choice after refusal. |
| S17 | `S17_walk_005`, `_030`, `_060` | Walking 5 / 30 / 60 seconds with 50% guidance participation and physical contention. |
| S18 | `S18_batch_2`, `_4`, `_8` | Simultaneous arrival batches of 2 / 4 / 8 and equal durations enabling synchronized releases. |

Each regime has 24 members, two visits each, two equipment types with two units
each, fixed order, no substitutions, and 60 seconds of released recovery.
Visit durations are 120/180 seconds multiplied by declared pace factors.
S01 spreads arrivals over four hours; other regimes use one hour. S18 uses equal
pace; others retain the existing repeating 1.25/0.75/1.0 pace factors.
These are synthetic engineering choices, not calibrated gym measurements.

Arrival times vary across seeds. S18 samples conditional batch arrival times,
preserving ties within each batch. Thirty deterministic copies with different
IDs would not be independent evidence. S18 guarantees simultaneous demand,
not the same realized release pattern under every policy: autonomous contention
can break synchronization. The final partial batch is allowed by the generator;
24 members divides evenly by all three E01 batch sizes.

Each saved workload is reused for `self_directed`, `fcfs`, `spt`, `matching`, and
`robust`, with existing policy defaults. FCFS is the provisional comparison
reference. Thirty paired scenarios × ten regimes × five policies = **1,500
episodes per split**. Seeds 42–71 are development; 1042–1071 are validation.
No final test split is configured yet. Compare policies within a regime;
cross-regime changes are descriptive sensitivity analyses. Regimes share seeds
and must not be pooled as 300 independent replications. Validation selection
weights the ten regimes equally, not the four scenario IDs equally.

This is the shared-environment design: algorithms differ in their decision rule,
not in the gym world they are asked to handle. FCFS does not model acceptance,
walking risk, or stale observations when it ranks candidates, but those conditions
still exist in its episode. The custom scheduler may use richer observable
signals; it should not be the only policy exposed to realistic difficulty.

## Run and inspect

From `scheduling-experiments/`:

```bash
uv sync --python 3.12
uv run pytest
uv run gym-sched experiment --config configs/experiments/e01.yaml --split train --output outputs/experiments/e01-train
```

Always supply `--split`: omitting it runs both development and validation.
Use a new output path for each run. If `uv` itself fails but the project virtual
environment is already installed, the equivalent entry point is
`.venv/bin/python -m gym_sched.cli` and tests are `.venv/bin/python -m pytest`.

Open `report.html` or `report.md`. Inspect `comparisons.json` for paired intervals,
`manifest.json` for attempted runs and saved workloads, and individual `result.json`
files for all guardrails and subgroup results. Trace refusals and failed access
through `events.jsonl`. `tests/test_e01.py` includes a controlled fresh-observation
walking race and checks completion/audits across every regime and policy.

| Workbook outcome | Evidence |
| --- | --- |
| M01, primary | `mean_wait_seconds`, all entrants, paired by saved workload. |
| M02 | `p95_wait_seconds`, `max_wait_seconds`; inspect tails separately from mean. |
| M03 | `completion_rate`, `visit_completion_rate`, `abandonment_rate`. |
| M08 | Engine feasibility checks, artifact audits, participant and equipment-option subgroups. Three-mode and order-permission subgroup reporting remains future work. |
| M12 | Episode status/audits, measured decision latency and 100 ms overruns. |

For S17, `failed_claims` includes autonomous failures. Advice-linked failures
must have a non-null `recommendation_id` in `claim_failed` events; the total is
not the workbook's proposed advised-only failure rate. Walking time is excluded
from ready wait, so review `mean_walking_seconds` alongside M01. There are no
deadlines or abandonments configured in this first panel.

## Proceed after reviewing the pilot

1. Review each regime's completion, tails, failures, subgroup outcomes and latency.
   Estimate precision with `uv run gym-sched pilot-count --run
   outputs/experiments/e01-train --split train --baseline fcfs --candidate robust`.
2. Run the same panel with `--split validation` into a separate directory. Select
   a classical reference using `gym-sched select-validation --run <validation-dir>
   --candidates fcfs,spt,matching`. Do not select a winner from development means.
3. Set final sample sizes from paired precision, add unused test seeds, archive a
   source revision, and freeze the final protocol before evaluating those tests.
   E02's independent/tracking/time-focused fields are a separate extension.

S01's “all three modes” is only approximated by current participation semantics.
E01 establishes an existing-model baseline, not full coverage of every workbook
row's proposed realism. Synthetic pilot results do not establish real-gym benefit.

## Development evidence: 30 September 2026

Executed `--split train` into
`outputs/experiments/e01-train-20260930/`. The saved report is
[report.html](../outputs/experiments/e01-train-20260930/report.html), with paired
intervals in `comparisons.json`. All 1,500 episodes completed with no artifact
audit findings, 100% member/visit completion and no abandonment. Maximum measured
decision latency was 0.008899 seconds on this machine, below 100 ms. This is
observed pilot latency, not a runtime guarantee. All 89 tests passed, including
the optional Pareto tests; Ruff lint and formatting checks passed.

The quiet control and equal-duration batches do not distinguish the guided
ranking rules. Refusal-heavy guidance adds cooldown waiting relative to the
autonomous control under this model. Robust is not uniformly better: at
acceptance 0.60, its mean episode P95 is 240.15 s versus FCFS's 221.96 s. At
60-second walking, robust's mean wait is 82.73 s versus FCFS's 84.50 s, a small
descriptive difference. No reference has been selected from these development
results, and validation/test episodes have not been opened.

The intended S17 mechanism occurred: FCFS had 84/223/399 advice-linked failed
attempts across the 5/30/60-second regimes, respectively; robust had 77/206/366.
These are event counts over 30 episodes each, not failure rates. S04 refusal
events and S18 synchronized releases were also exercised by the regression tests.

The robust-versus-FCFS pilot precision command recommends the protocol's minimum
100 scenarios per regime at its default 30-second target half-width. This does
not power tail/subgroup outcomes or establish confidence in a null difference.
Review whether a 30-second precision target is useful for these small contrasts
before freezing final counts. The source repository currently has no committed
revision; source fingerprints are saved in manifests, but archive a commit
before a final study. The original workbook's Planned cells remain unchanged.
